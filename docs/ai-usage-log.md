# Журнал взаємодії зі штучним інтелектом у проєкті «PythonStart»

Відповідно до принципів академічної доброчесності та інженерної етики, усі фрагменти коду, оптимізовані за допомогою ШІ, зафіксовані нижче.

## Сесія 1. Генерація модуля REST API та відмовостійкості (fetch + async/await)
- **Дата:** 21 листопада 2026 р.
- **Модель генеративного ШІ:** Claude 4.8 Opus / Gemini 3.8 Flash
- **Завдання:** Створити асинхронний модуль `api.js` для завантаження програмістських підказок із відкритого REST API з обов'язковим обробленням помилок та перемиканням на автономний локальний fallback-об'єкт.
- **Використаний промпт (Prompt Engineering):**
  > «Напиши ES6-модуль `api.js` з експортованою функцією `fetchDailyTip()`. Використовуй сучасний синтаксис `async/await` та функцію `fetch()`. Забезпеч обов'язкову перевірку `response.ok`, перехоплення помилок через блок `try/catch` та повернення резервного об'єкта підказки при мережевих збоях (404/500/offline). Додай коментарі українською мовою.»
- **Критична верифікація згенерованого коду:**
  - *Виявлена проблема:* Початкова генерація не враховувала, що зовнішній API повертає масив із одного об'єкта `[{setup, punchline}]`, через що виникала помилка `undefined`.
  - *Внесене виправлення:* Додано перевірку `Array.isArray(data) ? data[0] : data`.
  - *Висновок верифікації:* Код успішно протестований у браузерних DevTools (вкладка Network, 200 OK та офлайн-режим).

## Сесія 2. Оптимізація та збереження прогресу у localStorage
- **Дата:** 21 листопада 2026 р.
- **Модель:** Claude Sonnet 4.6
- **Завдання:** Розширити модуль `state.js` методами збереження стану та обробки винятків при заблокованих cookies/localStorage.
- **Верифікація:** Обгорнуто виклики `localStorage.setItem` та `getItem` у захисні блоки `try/catch`.
