# Специфікація вимог та межі MVP навчального тренажера «PythonStart»

## 1. Опис освітньої проблеми (Problem Statement)
- **Проблема:** Учні 8–9 класів ЗЗСО та студенти-першокурсники педагогічних спеціальностей відчувають суттєві труднощі під час самостійного опанування базового синтаксису мови програмування Python через складність абстрактної термінології та відсутність миттєвого інтерактивного зворотного зв’язку під час виконання практичних вправ.
- **Потреба користувачів:** Мати доступний, україномовний, легкий вебінструмент із лаконічними теоретичними картками-підказками, модульними практичними вправами та зрозумілим автоматичним аналізом типових помилок без страху отримати низьку оцінку.
- **Рішення:** Розробка інтерактивного навчального вебзастосунку «PythonStart», що поєднує теоретичний модуль, блок вікторини та систему автоматичної перевірки синтаксису.

## 2. Цільова аудиторія (Користувацькі персони)
1. **Основний користувач (Учень 8–9 класу / Студент-початківець):**
   - *Характеристика:* вивчає основи програмування мовою Python («Змінні», «Типи даних», «Умовні оператори», «Цикли»);
   - *Потреби:* прості лаконічні пояснення, готові наочні приклади синтаксису, миттєве підтвердження правильності рішення, доброзичливі підказки у разі помилки.
2. **Додатковий користувач (Учитель інформатики ЗЗСО):**
   - *Характеристика:* проводить уроки інформатики за навчальною програмою МОН України;
   - *Потреби:* готовий вебінструмент для проведення 5–10 хвилинних інтерактивних розминок на уроці, можливість організації самостійної роботи школярів як за шкільними комп'ютерами, так і з мобільних телефонів.

## 3. Користувацькі історії (User Stories) та Критерії прийнятності (Acceptance Criteria)

### US-01. Каталог навчальних тем
- **Історія:** Як учень 8–9 класу, я хочу бачити на головній сторінці впорядкований каталог базових тем з Python, щоб швидко обрати потрібний розділ для навчання.
- **Пріоритет MoSCoW:** Must have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] На головній сторінці відображається перелік щонайменше з 4 базових тем Python («Змінні», «Типи даних», «Умовні оператори», «Цикли»).
  - [ ] Кожна картка теми містить зрозумілий заголовок, короткий опис (1–2 речення) та кнопку «Перейти до теми».
  - [ ] При натисканні на кнопку теми відкривається відповідний розділ із теорією та практичними завданнями.
  - [ ] Інтерфейс карток адаптований для екранів комп’ютера та смартфона.

### US-02. Теоретична довідка з прикладами коду
- **Історія:** Як учень, я хочу читати коротке теоретичне пояснення з прикладами коду перед початком вправи, щоб пригадати синтаксис мови Python та логіку конструкцій.
- **Пріоритет MoSCoW:** Must have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] Сторінка обраної теми містить стислий конспект ключових понять українською мовою.
  - [ ] Наведено щонайменше один форматований приклад робочого коду на Python з коментарем очікуваного виводу.
  - [ ] Блок містить секцію «Зверніть увагу» з попередженням про часті синтаксичні помилки новачків.
  - [ ] Під теоретичним блоком розташована помітна кнопка «Почати вправу».

### US-03. Проходження інтерактивної навчальної вправи
- **Історія:** Як учень, я хочу виконувати практичні вправи з Python безпосередньо у вікні тренажера, щоб закріпити теорію через розв'язання завдань.
- **Пріоритет MoSCoW:** Must have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] У вікні тренажера відображається текст навчальної задачі або кодовий фрагмент із питанням.
  - [ ] Реалізовано елементи взаємодії (кнопки вибору правильного варіанта або поле вводу значення).
  - [ ] Відображається номер поточного завдання із загальної кількості вправ у темі.
  - [ ] Кнопка «Перевірити відповідь» стає активною лише після вибору або введення варіанта.

### US-04. Миттєва автоматична перевірка відповіді
- **Історія:** Як учень, я хочу отримувати негайний результат перевірки після надсилання відповіді, щоб одразу знати свій результат.
- **Пріоритет MoSCoW:** Must have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] Час автоматичної перевірки введеної відповіді становить менше 0.5 секунди.
  - [ ] При правильній відповіді поле підсвічується зеленим кольором та виводиться напис «Правильно!».
  - [ ] Користувачеві нараховується заліковий бал.
  - [ ] Забезпечено захист від помилок обробки при випадкових зайвих пробілах або різному регістрі літер.

### US-05. Пояснення помилки при неправильній відповіді
- **Історія:** Як учень, я хочу бачити коротке текстове пояснення у разі помилки, щоб усвідомити прогалину в знаннях і запам'ятати правильне правило.
- **Пріоритет MoSCoW:** Should have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] При виборі неправильної відповіді елемент виділяється червоним кольором та виводиться повідомлення з аналізом помилки.
  - [ ] Система відображає правильний розв'язок із коротким коментарем (чому саме так).
  - [ ] Надається кнопка переходу до наступного завдання або можливість спробувати знову.

### US-06. Підсумок проходження блоку завдань
- **Історія:** Як учень, я хочу бачити підсумковий результат після завершення всіх питань розділу, щоб об'єктивно оцінити свій поточний рівень засвоєння теми.
- **Пріоритет MoSCoW:** Should have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] Після останнього питання відкривається екран успішності із зазначенням набраних балів та відсотка правильності.
  - [ ] Залежно від відсотка формується мотивуюча підсумкова порада («Відмінно!», «Гарний результат, але повторіть цикли»).
  - [ ] Додано кнопку «Повернутися до каталогу тем» та кнопку «Пройти тему повторно».

### US-07. Методична інструкція користувача для вчителя та учня
- **Історія:** Як учитель інформатики, я хочу мати готову коротку інструкцію із застосування тренажера, щоб без затримок провести навчальну сесію на уроці.
- **Пріоритет MoSCoW:** Should have (MVP v1.0)
- **Критерії прийнятності:**
  - [ ] У репозиторії оформлено файл docs/instruction.md зі структурою завдань та критеріями оцінювання.
  - [ ] Наведено чіткі рекомендації щодо регламенту 10-хвилинної розминки на уроці інформатики.
  - [ ] Описано кроки запуску тренажера як на комп'ютері, так і зі смартфона.

### US-08. Автоматичне збереження локального прогресу
- **Історія:** Як учень, я хочу, щоб мої результати зберігалися у браузері, щоб при оновленні сторінки не починати проходження заново.
- **Пріоритет MoSCoW:** Could have (Версія 1.1)
- **Критерії прийнятності:**
  - [ ] Історія виконаних тем та найкращі бали зберігаються у Web Storage (localStorage).
  - [ ] На головній сторінці біля вивчених тем з'являється позначка пройденого матеріалу.

### US-09. Гейміфікація та оформлення (бейджі, темна тема)
- **Історія:** Як учень, я хочу отримувати цифрові бейджі досягнень та перемикати темний режим сайту, щоб навчання було цікавішим і комфортнішим для очей.
- **Пріоритет MoSCoW:** Could have (Версія 1.2)
- **Критерії прийнятності:**
  - [ ] Реалізовано перемикач світлої/темної колірної теми.
  - [ ] Додано віртуальні нагороди за 100% правильних відповідей.

### US-10. Особистий кабінет учня та інтеграція з журналом
- **Історія:** Як учитель, я хочу мати централізований кабінет моніторингу класу з вивантаженням оцінок у шкільну систему, щоб автоматизувати документообіг.
- **Пріоритет MoSCoW:** Won’t have this time (Майбутні версії)
- **Критерії прийнятності:**
  - [ ] Функціонал серверної бази даних, авторизації та експорту оцінок відкладено на наступні версії після тестування MVP.

- **За межами MVP v1.0 залишаються:** US-08, US-09, US-10.
